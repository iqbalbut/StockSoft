# Extraction: prompt, schema, test cases

- **Prompt:** [`src/extraction/prompt.ts`](../src/extraction/prompt.ts). Byte-stable, so it is served from the prompt cache across a backlog run.
- **JSON schema:** [`src/extraction/schema.ts`](../src/extraction/schema.ts). `EXTRACTION_JSON_SCHEMA` is sent as `output_config.format` (structured outputs constrain the response to the shape), and `ExtractionSchema` (Zod) re-validates the meaning: dates are real `YYYY-MM-DD`, confidences are between 0 and 1, `card_last4` is exactly 4 digits.
- **Call:** [`src/extraction/extract.ts`](../src/extraction/extract.ts). Uses model `claude-opus-5-5` with adaptive thinking and `effort: medium`, all configurable. Server-side fallback (`fallbacks: "default"`) is on, so a safety-classifier decline is retried on Anthropic's recommended fallback model instead of failing. If the output is cut off or fails validation, the error is sent back to the model and it is asked again (up to `EXTRACTION_MAX_ATTEMPTS`). A refusal is permanent and the document is marked failed for a human to handle.
- **Sanitising:** [`src/extraction/sanitize.ts`](../src/extraction/sanitize.ts) masks any Luhn-valid card number or IBAN that reaches free-text fields, as a second guard behind the prompt rule.

## Output fields

`document_type` (expense_receipt, vendor_bill, sales_invoice, bank_statement, contract, other), `issued_by_us`, `language`, `image_quality`, `vendor_name`, `vendor_tax_id`, `document_number`, `document_date`, `due_date`, `currency`, `subtotal`, `tax`, `tip`, `total`, `payment_method`, `card_last4`, `line_items[]`, `client_reference`, `category` (IRS Schedule C-mapped, see `CATEGORIES`), `is_business`, `is_billable`, `confidence{…per field…}`, `notes`.

## How confidence becomes routing

[`src/pipeline/route.ts`](../src/pipeline/route.ts): a document is auto-approved only if **every** critical field (type, vendor, date, currency, total, category) is at or above the threshold (default 0.90) **and** none of these flags is raised: total missing, totals don't add up, poor image, looks personal, not a receipt/bill/invoice, no FX rate, USD amount over the review limit (default $500), possible duplicate. A field a human has confirmed, or a learned vendor rule, counts as 1.0.

Model confidence is self-reported, so it is a useful signal, not a guarantee. The safeguard is the eval below: its key number is **silent errors**, meaning wrong values the model was at least 90% sure of, because those are the ones that would be filed without review. Raise the threshold in Settings if real-world receipts produce any.

## The 10 test cases

Defined in [`src/extraction/test-cases.ts`](../src/extraction/test-cases.ts), with images in `fixtures/images/` (synthetic, generated by `npm run fixtures`. Replace any with a real photo of the same kind to test on real paper).

| # | Case | Tests | Expected route |
|---|---|---|---|
| 01 | SaaS invoice, USD, card | clean baseline, card last-4 | auto-approve |
| 02 | Lahore restaurant, PKR, GST 16%, tip | PKR, tax + tip arithmetic, masked card | auto-approve |
| 03 | **Blurry** café receipt | low confidence must not be guessed | review |
| 04 | **Urdu-only** stationery receipt, Urdu digits | Urdu reading, digit conversion, romanised vendor | review (vendor romanisation < 90%) |
| 05 | **PKR internet bill** with due date + FED | vendor bill, due date, tax | auto-approve (→ payables in Phase 2) |
| 06 | **Duplicate** of #02 (faded re-scan) | fuzzy duplicate across different files | duplicate |
| 07 | Faded thermal Dubai taxi, AED, VAT | contrast recovery, AED | auto-approve |
| 08 | **Handwritten** contractor receipt "Acme Retail project" | handwriting, billable + client reference, d/m date | review |
| 09 | Sales invoice **issued by AiNetworks**, GBP | outgoing invoice detection, revenue | review (over $500) |
| 10 | UK hotel, 03/04/2026, GBP | ambiguous day/month, VAT-inclusive totals | review |

Two ways to run them:

```bash
npm test                    # offline: routing, duplicates, FX, audit, vendor learning, using the simulated responses
ANTHROPIC_API_KEY=... npm run eval:extraction   # live model: field accuracy + silent errors, saved to fixtures/eval-results.json
```

The live eval has **not** been run while building this (no API key in the build environment). Run it once with your key before relying on auto-approval, and again whenever you change the prompt or model.
